### Описание проблемы
Многие любители шахмат хотят играть в любое удобное время, без поиска соперника онлайн и без регистрации. Существующие приложения либо требуют постоянного интернета для игры с живыми людьми, либо имеют слишком сложный интерфейс, либо предлагают ограниченный выбор уровней сложности бота.

### Цели проекта
Создать простое, удобное мобильное приложение для игры в классические шахматы против ИИ-бота с настраиваемым уровнем сложности. Приложение должно быть максимально готово к оффлайн-использованию (кроме вызова API бота).

### Задачи проекта
- Реализовать два основных экрана
- Обеспечить корректную работу шахматных правил (валидация ходов, определение окончания партии)
- Интегрировать приложение с предоставленным серверным API бота

## 3. Функциональные требования

### Основные функции приложения

1. Экран выбора сложности
2. Игровой экран
3. Выбор уровня бота (1–8)
4. Запуск партии
5. Отображение шахматной доски (drag-and-drop или tap-to-move)
6. Автоматический ход бота через вызов API
7. Кнопка «Назад» (отмена одного полухода)
8. Кнопка «Заново» (возврат к начальной позиции)
9. Кнопка «Сдаться» (возврат на экран выбора сложности)
10. Кнопка «Поменять цвет»
11. Локальное определение окончания партии (мат, пат и др.)

### Сценарии использования (Use Cases)

**UC-01. Запуск приложения**  
Пользователь открывает приложение → отображается экран выбора сложности.

**UC-02. Выбор уровня сложности**  
Пользователь выбирает уровень 1–8 (выделяется выбранный вариант).  
После выбора активируется кнопка «Играть».

**UC-03. Начало партии**  
Нажатие «Играть» → переход на игровой экран.  
Доска загружается в начальную позицию:  
`rnbqkbnr/pppppppp/8/8/8/8/PPPPPPPP/RNBQKBNR w KQkq - 0 1`  
Игрок играет белыми, бот — чёрными.  
Сверху: аватар и никнейм бота («Бот уровня X»)  
Снизу: аватар и никнейм игрока («Вы» — для MVP задаётся статически)

**UC-04. Ход игрока**  
Игрок делает ход → проверка легальности (библиотека chess).  
При легальном ходе:
- обновляется FEN
- отправляется запрос к API (FEN + уровень сложности)
- полученный ход бота применяется автоматически
- проверяется окончание партии

**UC-05. Отмена хода**  
Нажатие «Назад» → отменяется последний полуход (восстанавливается предыдущий FEN).  
Если отмена после хода бота → отменяются оба полухода.

**UC-06. Перезапуск партии**  
Нажатие «Заново» → доска возвращается в начальную позицию, история очищается.

**UC-07. Сдача партии**  
Нажатие «Сдаться» → партия завершается (победа бота), возврат на экран 1.

**UC-08. Окончание партии**  
При мате / пате / других правилах ничьей → показывается модальное окно с результатом и кнопкой «Новая партия» (возврат на экран 1).

## 4. Нефункциональные требования

### Производительность
- Отклик интерфейса ≤ 100 мс
- Время хода бота зависит только от сервера (показывать индикатор загрузки)
- Поддержка устройств с ≥ 2 ГБ RAM

### Безопасность
- Все вызовы API только по HTTPS
- Не хранить токены, пароли и другие чувствительные данные
- Валидация всех входных и выходных данных

### Удобство использования (Usability)
- Интуитивный интерфейс (стандартные шахматные жесты)
- Только портретная ориентация
- Адаптивный дизайн под разные размеры экранов
- Подсказки при первом запуске (опционально)

### Поддерживаемые платформы
- Android 8.0+ (API 26+)
- iOS 12.0+
- Телефоны и планшеты (желательна оптимизация под планшеты)

┌─────────────────────────▼────────────────────────────────┐

**Обязанности слоёв:**

| Слой            | Обязанности                                   | Правила коммуникации                              |
|-----------------|-----------------------------------------------|---------------------------------------------------|
| **UI Layer**    | Отображение данных, обработка ввода           | Отправляет Commands/Queries в Logic Layer         |
| **Logic Layer** | Бизнес-логика, обработка команд               | Принимает от UI, читает/пишет в Data Layer        |
| **Data Layer**  | Вызовы API, операции с локальными данными     | Общается только с Logic Layer                     |

### 6.3 Паттерн CQRS с Mediator (пакет streamline)

#### 6.3.1 Почему streamline?

Пакет **[streamline](https://pub.dev/packages/streamline)** выбран потому что он:

- ✅ **MIT лицензия** (в отличие от AGPL-альтернатив)
- ✅ **Автоматическая регистрация handlers** через code generation
- ✅ Настоящий **CQRS/Mediator**-паттерн как в .NET MediatR
- ✅ Разделяет **Commands** (запись) и **Queries** (чтение)
- ✅ Поддерживает **Domain Events** для перерисовки UI
- ✅ Поддерживает **pipeline behaviors** (logging, validation, caching)

#### 6.3.2 Поток CQRS

```
┌──────────────────────────────────────────────────────────────────┐
│ UI Layer                                                         │
│ [ChessBoard] [Buttons] [DifficultySelector]                      │
└────────────────────────────┬─────────────────────────────────────┘
                             │ User Action
                             ▼
┌──────────────────────────────────────────────────────────────────┐
│ Mediator (streamline)                                            │
│ ┌────────────────────────────────────────────────────────────┐   │
│ │ Commands (write operations):                               │   │
│ │ - MakeMoveCommand                                          │   │
│ │ - UndoCommand                                              │   │
│ │ - RestartCommand                                           │   │
│ │ - ResignCommand                                            │   │
│ │ - SetBotLevelCommand                                       │   │
│ └────────────────────────────────────────────────────────────┘   │
│ ┌────────────────────────────────────────────────────────────┐   │
│ │ Queries (read operations):                                 │   │
│ │ - GetCurrentFenQuery                                       │   │
│ │ - GetGameStatusQuery                                       │   │
│ │ - GetBotLevelQuery                                         │   │
│ └────────────────────────────────────────────────────────────┘   │
│ ┌────────────────────────────────────────────────────────────┐   │
│ │ Domain Events (trigger UI rebuilds):                       │   │
│ │ - GameStateChangedEvent                                    │   │
│ │ - GameOverEvent                                            │   │
│ │ - BotLevelChangedEvent                                     │   │
│ └────────────────────────────────────────────────────────────┘   │
└────────────────────────────┬─────────────────────────────────────┘
                             │
                             ▼
┌──────────────────────────────────────────────────────────────────┐
│ Command/Query Handlers                                           │
│ (Business Logic - validate, coordinate, transform)               │
└────────────────────────────┬─────────────────────────────────────┘
                             │
                             ▼
┌──────────────────────────────────────────────────────────────────┐
│ Data Layer                                                       │
│ ┌──────────────────┐  ┌──────────────────┐                       │
│ │ Services         │  │ Repositories     │                       │
│ │ - ApiService     │  │ - LocalStorage   │                       │
│ │ - BotService     │  │ (optional)       │                       │
│ └──────────────────┘  └──────────────────┘                       │
└──────────────────────────────────────────────────────────────────┘
```

#### 6.3.3 Описание компонентов

- **Commands** — неизменяемые объекты действий, меняющих состояние  
  Примеры: `MakeMoveCommand`, `UndoCommand`, `ResignCommand`
- **Queries** — неизменяемые запросы на данные  
  Примеры: `GetCurrentFenQuery`, `GetGameStatusQuery`
- **Handlers** — классы с бизнес-логикой, зависимости через constructor injection
- **Domain Events** — публикуются после успешной команды, вызывают rebuild UI через `QueryBuilder`

### 6.4 Dependency Injection (get_it + injectable)

#### 6.4.1 Почему get_it + injectable?

| Возможность               | get_it + injectable       | Provider              |
|---------------------------|---------------------------|-----------------------|
| **Pattern**               | Service Locator           | InheritedWidget       |
| **Auto-registration**     | ✅ code generation        | ❌ ручная            |
| **BuildContext required** | ❌                        | ✅                   |
| **Use in pure Dart**      | ✅                        | ❌                   |
| **Constructor injection** | ✅ автоматическая         | ❌ ручная            |
| **Learning curve**        | низкая (как .NET DI)      | средняя               |

#### 6.4.2 Как работает

1. Аннотации: `@injectable`, `@lazySingleton`, `@singleton`
2. `flutter pub run build_runner build`
3. Вызов `configureDependencies()` / `init()` при старте
4. `getIt<MyService>()` в любом месте

### 6.5 Services vs Repositories

#### 6.5.1 Services (основной доступ к данным)

**ChessService** — все API-вызовы:
- `getGameSession(level)`
- `makeMove(sessionId, from, to)`
- `getFen(sessionId)`
- `getGameStatus(sessionId)`

#### 6.5.2 Почему Services, а не Repositories в MVP

| Аспект              | Repository       | Service         | Решение ChessBot |
|---------------------|------------------|-----------------|------------------|
| Источник данных     | локальное        | HTTP API        | ✅ API           |
| Где состояние       | локально         | на сервере      | ✅ сервер        |
| Offline support     | обязательно      | опционально     | ❌ не нужно      |
| Кэширование         | встроенное       | ручное          | ❌ не нужно      |

**Вывод для MVP:** Services напрямую в Handlers, repositories — опционально позже.

### 6.6 Управление состоянием UI (Provider + ChangeNotifier)

Два механизма обновления UI:

| Механизм                  | Назначение                     | Триггер                          |
|---------------------------|--------------------------------|----------------------------------|
| **Domain Events** (streamline) | данные изменились            | завершение Command               |
| **ChangeNotifier** (Provider)  | UI-состояние (loading, error) | `notifyListeners()`              |

**ViewModel** (только в UI-слое):
- `isLoading`
- `error`
- `showDialog`
- `selectedLevel`

Handlers и сервисы **не используют** ChangeNotifier.

### 6.7 Навигация — go_router

Преимущества:
- deep linking
- browser history (web)
- nested routes
- route guards
- доступ без BuildContext

Маршруты:
- `/difficulty`
- `/game?level=X`

### 6.8 Unidirectional Data Flow

```
UI → Command → Mediator → Handler → Service → API
↓
Domain Event → QueryBuilder → rebuild UI
```

UI никогда не меняет данные напрямую.
