# Техническое задание (ТЗ)  
**Мобильное приложение «ChessBot»**

**Версия ТЗ:** 1.0  
**Дата:** 26 февраля 2026 г.

## 1. Введение

### Описание проблемы
Многие любители шахмат хотят играть в любое удобное время, без поиска соперника онлайн и без регистрации. Существующие приложения либо требуют постоянного интернета для игры с живыми людьми, либо имеют слишком сложный интерфейс, либо предлагают ограниченный выбор уровней сложности бота.

### Цели проекта
Создать простое, удобное мобильное приложение для игры в классические шахматы против ИИ-бота с настраиваемым уровнем сложности. Приложение должно быть максимально готово к оффлайн-использованию (кроме вызова API бота).

### Задачи проекта
- Реализовать два основных экрана  
- Обеспечить корректную работу шахматных правил (валидация ходов, определение окончания партии)  
- Интегрировать приложение с предоставленным серверным API бота

## 2. Целевая аудитория

- **Возраст:** 12–65 лет  
- **Интересы:** шахматы, стратегия, развитие логического мышления, тренировка навыков  
- **Потребности:**  
  - Быстро начать игру  
  - Выбор уровня сложности (от новичка до продвинутого)  
  - Удобное управление на мобильном устройстве  
  - Минимум настроек и лишних экранов

## 3. Функциональные требования

### Основные функции приложения

1. Экран выбора сложности  
2. Игровой экран  
3. Выбор уровня бота (1–8)  
4. Запуск партии  
5. Отображение шахматной доски (drag-and-drop или tap-to-move)  
6. Автоматический ход бота через вызов API  
7. Кнопка «Назад» (отмена одного полухода)  
8. Кнопка «Заново» (возврат к начальной позиции)  
9. Кнопка «Сдаться» (возврат на экран выбора сложности)  
10. Кнопка «Поменять цвет»  
11. Локальное определение окончания партии (мат, пат и др.)

### Сценарии использования (Use Cases)

**UC-01. Запуск приложения**  
Пользователь открывает приложение → отображается экран выбора сложности.

**UC-02. Выбор уровня сложности**  
Пользователь выбирает уровень 1–8 (выделяется выбранный вариант).  
После выбора активируется кнопка «Играть».

**UC-03. Начало партии**  
Нажатие «Играть» → переход на игровой экран.  
Доска загружается в начальную позицию:  
`rnbqkbnr/pppppppp/8/8/8/8/PPPPPPPP/RNBQKBNR w KQkq - 0 1`  
Игрок играет белыми, бот — чёрными.  
Сверху: аватар и никнейм бота («Бот уровня X»)  
Снизу: аватар и никнейм игрока («Вы» — для MVP задаётся статически)

**UC-04. Ход игрока**  
Игрок делает ход → проверка легальности (библиотека chess).  
При легальном ходе:  
- обновляется FEN  
- отправляется запрос к API (FEN + уровень сложности)  
- полученный ход бота применяется автоматически  
- проверяется окончание партии

**UC-05. Отмена хода**  
Нажатие «Назад» → отменяется последний полуход (восстанавливается предыдущий FEN).  
Если отмена после хода бота → отменяются оба полухода.

**UC-06. Перезапуск партии**  
Нажатие «Заново» → доска возвращается в начальную позицию, история очищается.

**UC-07. Сдача партии**  
Нажатие «Сдаться» → партия завершается (победа бота), возврат на экран 1.

**UC-08. Окончание партии**  
При мате / пате / других правилах ничьей → показывается модальное окно с результатом и кнопкой «Новая партия» (возврат на экран 1).

## 4. Нефункциональные требования

### Производительность
- Отклик интерфейса ≤ 100 мс  
- Время хода бота зависит только от сервера (показывать индикатор загрузки)  
- Поддержка устройств с ≥ 2 ГБ RAM

### Безопасность
- Все вызовы API только по HTTPS  
- Не хранить токены, пароли и другие чувствительные данные  
- Валидация всех входных и выходных данных

### Удобство использования (Usability)
- Интуитивный интерфейс (стандартные шахматные жесты)  
- Только портретная ориентация  
- Адаптивный дизайн под разные размеры экранов  
- Подсказки при первом запуске (опционально)

### Поддерживаемые платформы
- Android 8.0+ (API 26+)  
- iOS 12.0+  
- Телефоны и планшеты (желательна оптимизация под планшеты)

# Архитектура приложения «ChessBot» — вариант MVC

## Основные слои и их ответственность

### 1. Model (Модель)
Содержит данные, бизнес-логику и состояние игры.  
Не знает ничего об интерфейсе и о том, как данные отображаются.

**Основные сущности и обязанности Model:**

- `GameState` / `ChessGame`
  - Текущая позиция (FEN-строка)
  - История ходов (`List<String>` с FEN-позициями для функции «Назад»)
  - Текущий уровень сложности бота (1–8)
  - Кто ходит сейчас (белые / чёрные)
  - Статус партии (active, checkmate, stalemate, draw, resigned и т.д.)

- `ChessRulesService`
  - Валидация ходов (использует библиотеку `chess`)
  - Генерация легальных ходов для подсветки
  - Определение окончания партии (мат, пат, троекратное повторение и др.)

- `BotService`
  - Отправка запроса к API (FEN + уровень сложности)
  - Получение и парсинг хода бота (SAN → применение на доске)
  - Логика ожидания ответа и таймаутов (опционально)

- `Settings` (или часть GameState)
  - Выбранный никнейм игрока (для MVP — статический)
  - Предпочтения (тема доски, если будет)

### 2. View (Представление)
Отвечает только за отображение и сбор пользовательского ввода.  
Не содержит бизнес-логики и не меняет данные напрямую.

**Основные экраны и виджеты:**

- `DifficultyScreen` (экран выбора сложности)
  - Список карточек уровней 1–8
  - Кнопка «Играть» (активна только после выбора)

- `GameScreen`
  - Аватар и ник бота (верх)
  - Шахматная доска (`flutter_chess_board` / `chessground`)
  - Аватар и ник игрока (низ)
  - Панель управления:
    - Сдаться
    - Назад
    - Заново
  - Оверлей/диалог окончания партии

- Общие компоненты
  - `ChessBoardWidget` — обёртка над доской с обработкой жестов
  - `PlayerInfoWidget` — аватар + имя
  - `ControlButton` — стилизованные кнопки управления

View только:
- показывает текущее состояние из Controller
- передаёт пользовательские действия (onMove, onUndo, onResign и т.д.) в Controller

### 3. Controller (Контроллер / Presenter)

Обрабатывает события от пользователя, обновляет модель и говорит View, что нужно перерисовать.

**Основные контроллеры:**

- `DifficultyController`
  - Хранит выбранный уровень (1–8)
  - Реагирует на выбор уровня → активирует кнопку «Играть»
  - При нажатии «Играть» → создаёт новый `GameController` и переходит на игровой экран

- `GameController`
  - Инициализация новой партии (начальный FEN, белые ходят)
  - Обработка хода игрока:
    1. Проверяет легальность через `ChessRulesService`
    2. Если легально → обновляет `GameState`
    3. Запускает ход бота (асинхронно)
  - Обработка хода бота:
    1. Вызов `BotService`
    2. Применение полученного хода
    3. Проверка окончания партии
  - Команды интерфейса:
    - `undo()` → восстанавливает предыдущий FEN
    - `restart()` → сбрасывает до начальной позиции
    - `resign()` → завершает партию → возврат на выбор сложности
  - Слушает изменения в `GameState` и уведомляет View (через `setState`, `ValueNotifier`, `Provider`, `Riverpod` и т.д.)

## Поток типичного сценария (пример хода игрока)

1. Пользователь перетаскивает фигуру → `ChessBoardWidget` вызывает callback `onMoveAttempt(from, to)`
2. `GameController` получает событие → передаёт в `ChessRulesService.isLegalMove()`
3. Если ход легален:
   - `GameState.applyMove()` → обновляется FEN и история
   - `GameController` запускает `BotService.makeBotMove()`
   - Показывается индикатор загрузки
4. Пришёл ответ от API → `GameState.applyBotMove(uciMove)`
5. Проверяется статус партии → если окончена → показывается диалог
6. View автоматически перестраивается (реактивно)

## Преимущества такого подхода в контексте приложения

- Чёткое разделение: UI не знает про API, правила шахмат и историю
- Легко тестировать `GameController` и `Model` без UI
- Функция «Назад» реализуется просто (список FEN)
- Stateless API идеально вписывается — каждый ход = независимый запрос
- Легко добавить потом «Поменять цвет», анализ позиции, сохранение партии и т.д.
